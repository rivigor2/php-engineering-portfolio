# Почему HTTP 200 недостаточно для приёмки

В материалах процесса разработки с ИИ зафиксирован класс ошибки: агент закрывает шаг по наличию кнопки или успешному HTTP-ответу, хотя полный пользовательский сценарий не реализован. Из этого следует правило полноты: если действие входит в scope, проверяется вся цепочка до наблюдаемого результата.

Ниже — иллюстрация этого класса. Это не реконструкция конкретного инцидента с известным root cause.

## Пример критерия

**Недостаточно:** «Кнопка повтора существует, endpoint отвечает 200».

**Проверяемый результат:** «Оператор повторяет неуспешную операцию; создаётся одна связанная операция, строка меняет состояние, повторный вход показывает тот же результат».

Приёмка связывает действие пользователя, HTTP-контракт, сохранённое состояние и живой интерфейс. Успешный ответ одного слоя не закрывает остальные.

## Как правило применяется

Постановщик задаёт критерий с ID. Исполнитель записывает в STEP команду или сценарий, полученный результат и ограничения. Ревьюер видит, какие части проверены автоматически, а где ещё нужен человек.

В [разборе stage-прогона](example-run/07-step-report.md) это различие видно на практике: HTTP дополняет настоящий браузер; детерминированное прохождение явно отделено от обычного UI; техническое завершение не закрывает независимый review предыдущего шага.

## Ещё одна ошибка: проверили другой проект

В том же исходном отчёте удалённая проверка вернула успешный статус, но другую привязку проекта. Исполнитель не зачёл её и сверил локальный план отдельно.

Вывод для приёмки: проверяется не только PASS, но и то, к какому объекту этот PASS относится. Исправление общей карты проектов не включается в задачу молча.
