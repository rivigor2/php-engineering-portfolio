# Интернет-магазин ↔ торговая площадка

В коммерческом проекте я разрабатывал выгрузку каталога и обработку заказов внешней торговой площадки. Один из предметных дефектов: дата и интервал доставки из входящего заказа не попадали в карточку магазина. Сотруднику было трудно понять, когда готовить заказ. Нужно было сопоставить поля API с моделью заказа, сохранить время доставки и сделать его доступным сотруднику.

Клиент и интеграционный партнёр обезличены. Код ниже написан заново на синтетических данных; корпоративные исходники и закрытый API-контракт не публикуются. Моя часть работы — получение заказа, передача интервала доставки и исправления расхождений наличия.

## Главный сценарий — открыть код

1. [ReceiveMarketplaceOrder](src/Application/ReceiveMarketplaceOrder.php) — входящий заказ превращается в нормализованные данные первого события;
2. [MapIncomingOrder](src/Application/MapIncomingOrder.php) и [DeliveryWindow](src/Domain/DeliveryWindow.php) — строки, источник, цена и явный временной интервал в часовом поясе магазина;
3. [ProcessOrderEvent](src/Application/ProcessOrderEvent.php) — одна транзакция для состояния, данных заказа и результата события;
4. [PdoOrderRepository](src/Infrastructure/SQLite/PdoOrderRepository.php) — сохранённые строки заказа и доставка вместе с состоянием;
5. [OrderEvent](src/Domain/OrderEvent.php) и [MarketplaceOrder](src/Domain/MarketplaceOrder.php) — полный хеш нормализованных данных и допустимые переходы;
6. [CLI-сценарий](bin/marketplace-order.php) и [его данные](examples/order-lifecycle.json) — создание, повтор, ручной разбор и доставка.

```text
входящий заказ → нормализация → order_created с данными заказа
                                     ↓
                     одна SQLite-транзакция
                 состояние + строки/доставка + receipt
                                     ↓
                     дальнейшие события заказа
```

## Как посмотреть результат

Из корня репозитория:

```bash
php current-experience/ecommerce-marketplace/bin/marketplace-order.php
```

Сценарий записывает данные в `var/marketplace-order.sqlite` и выводит JSON после каждого шага: решение, переход, фактически сохранённое состояние и данные заказа с доставкой. Повтор той же команды использует ту же БД: заказ не пересоздаётся, сохранённые receipt показывают идемпотентность сценария.

Ожидаемый маршрут вымышленного заказа: создание → подтверждение → повтор подтверждения → преждевременная доставка с `manual_review` → оплата → сборка → готовность → курьер → доставка. Входной интервал 14:00–15:00 с UTC+3 сохраняется как 13:00–14:00 в Europe/Kaliningrad.

## Решения и ограничения

- `awaiting_creation` отделено от первого `order_created`;
- событие хешируется вместе со всеми нормализованными предметными данными; порядок ключей JSON-объекта не создаёт конфликт;
- повтор проверяется в [постоянном receipt](src/Infrastructure/SQLite/PdoEventReceiptRepository.php); у агрегата нет второй памяти event ID;
- одинаковый event ID с другими данными отклоняется;
- повторное создание не заменяет уже сохранённые строки и доставку; изменение заказа должно иметь отдельную команду;
- данные заказа, состояние и receipt коммитятся вместе; ошибка записи откатывает весь текущий шаг;
- повтор ранее сохранённого `manual_review` остаётся ручным разбором, а не превращается в успех;
- пример рассчитан на последовательный локальный обработчик, не заявляет распределённое exactly-once;
- резервирование склада, полный Bitrix-адаптер и операторский replay в этот срез не входят.

SQLite, автомат и receipt — выбранные решения публичного примера. Они не заявляются точной архитектурой рабочего проекта.

## Другие фрагменты этой линии

- [ImportCatalog](src/Application/ImportCatalog.php) и [хранилище каталога](src/Infrastructure/SQLite/PdoCatalogRepository.php): частичный результат импорта, версии товаров, конфликт одинаковой версии с разными данными.
- [CompositeAvailability](src/Domain/CompositeAvailability.php): доступность составного товара по ограничивающему компоненту.
- [DispatchOutboundMessage](src/Application/DispatchOutboundMessage.php), [RetryPolicy](src/Application/RetryPolicy.php) и [outbox](src/Infrastructure/SQLite/PdoOutboxRepository.php): доставка, классификация ответа, повтор после сбоя и сохранение результата.
- [HTTP transport](src/Infrastructure/Http/StreamHttpTransport.php): отдельная граница внешнего вызова.

Это самостоятельные дополнительные фрагменты линии интеграции. Внешняя доставка из outbox не входит в транзакцию главного сценария заказа.
